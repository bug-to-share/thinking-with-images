# 医学 Thinking-with-Images：技术复盘与研究方向

文献检索截止 2026-11-14；仓库整理 2026-11-24。历史数值不等于本次重新复现。


## 二 已经完成的工作

### 1 医学数据构建与难度筛选

从医学分割数据的图像、mask、ROI 和结构描述出发，构建统一预处理及采样流程。已有日志记录扫描去重后 269,096 条、平衡采样后 59,978 条；主 VQA 池实际保留 **9,997 条**。前两个数字是不同处理阶段的条目数，不代表 26.9 万张独立影像，也不能说它们全部用于训练。

另一条数据线对公开医学 VQA 进行多次采样筛选。以 8 次回答的一致性或正确数为依据，将易题、具有学习信号的中等题和难题分流。已有 OmniMedVQA 与 SLAKE/VQA-RAD 的筛选产物。后续 CoT 实验进一步保留了 medium、medium+hard 等数据方案，用来检验训练难度分布与 reward 的关系。

对外可表述为“搭建医学 VQA 数据构建与多次采样筛选流水线，形成约 1 万条项目内问答池”。合成数据质量、图像级独立性和真正的 OOD 能力仍需独立测量。

### 2 可执行的多模态工具环境

核心能力是模型可以在推理中调用 Python 图像处理、BioMedParse、MedSAM3 和知识检索；工具返回 mask、overlay、bbox、状态或文本证据后，Agent 将新图像真正送入下一轮模型输入。不同实验的启用工具集合不同，不能说每个 checkpoint 都训练过全部工具。

重型分割模型通过服务与策略模型解耦，工具调用、执行结果和后续回答保留在 trace 中。后续实验区还实现了更轻的 `zoom_in` 与 `retrieve` 两工具 recipe；其中检索使用 SLAKE 英文知识图谱事实表，不直接索引问答答案。

```text
原始图像与问题
    ↓
视觉语言模型生成理由和动作
    ↓
动作解析与工具调度 → 执行分割／裁剪／代码／检索
    ↑                              ↓
下一轮模型输入 ← 新图像＋结构化观察＋历史状态
    ↓
最终答案 → 答案评分、格式评分、工具行为统计 → SFT／GRPO
```

### 3 坐标协议与教师轨迹

在 Gemini 教师线引入等比缩放并 padding 到 **1000×1000 working canvas**，统一模型看见的图、工具操作的图与返回坐标。Gemini 的 `[ymin,xmin,ymax,xmax]` 与 Qwen 的 `[x1,y1,x2,y2]` 通过适配层转换，而不是直接混用。

轨迹生成包含真实工具执行和结果回注，并增加格式、工具必要性、观察整合等检查。较完整的一次冷启动数据链为 **1,995 条来源轨迹 → 1,805 条 verifier pass → 1,791 条最终 SFT 输入样本**。该批最终 precheck 使用 `skip_llm=true`，属于规则检查；另有小批量 LLM verifier 探索。不同阶段不能混为一谈，规则得分也不能视为独立 LLM 评审、医生审核或真实推理正确率。

部分教师运行采用 `with_answer`，可读取参考答案或参考框。这适合产生候选监督，但其正确率只能说明受答案辅助的轨迹生成情况；不能作为无答案提示的学生模型成绩。将其转成学生数据时还需要检查是否复制了不可由图像和实际工具观察支持的解释。

### 4 LoRA SFT 与多轮 GRPO

已使用 LlamaFactory 完成 Qwen3-VL 冷启动 LoRA SFT，并留下训练配置、adapter 与训练指标。除 8B 的 1,791 条 Gemini 轨迹输入外，还有 4B full-trace 分支：10,019 个来源轨迹文件中 9,154 个可用，剔除 1 例图像 token 不匹配后形成 9,153 条最终数据，并保存完成 1 epoch 的训练指标；它和 1,791 条分支是不同实验，不能相加当成去重总量。SFT 的直接目标是让模型学会动作协议、工具结果消费和结束回答。

在 VERL 中接入医学数据适配、工具 schema、SGLang 多轮 rollout、自定义 reward、验证与 checkpoint，保留 4B/8B、不同工具组合及 judge 方案的实验。部分旧 Agent 运行曾使用 SLAKE test 的 500 题子集作为训练期 validation，这进一步限制了将旧结果作为未触碰 test 的主张。后续独立实验区的 Agent 日志实际到 step 51，checkpoint 保存至 step 50；该步验证 correctness 66.67%、格式率 100%，但没有最终 test 表，运行也有多次恢复和工具服务异常。不能沿用某次启动失败就认定该分支始终没有训练成功，也不能把验证分数当成最终测试。

**早期 SFT 评测存在输入池重合。** 100 条 prompt-only 与 cold-start 对比样本全部出现在 1,791 条 SFT 输入池；该池还内部划出约 5% 验证样本，因此准确说法是“与 SFT 输入池完全重合”，不能断定这 100 条全部参加过梯度更新。原先“正确 39→46、格式错误事件 15→1”只能作为输入池上的协议回归观察；该脚本的 `correct_exact` 字段还包含语义 judge 校正，不能再称纯 EM。3,000 条混合评测也有重合，详见第四节。

### 5 CoT GRPO 与正式测试

后续在 `Med-Thinking-with-images` 中直接以官方 Qwen3-VL-4B-Instruct 为初始化开展显式 `<reason>/<answer>` CoT 训练，探索 EM reward、格式权重、KL、LLM judge 和数据筛选。原始展开配置支持它没有从上述受污染的 SFT 输入池所训练的 adapter 初始化。这里的“CoT”是有图像输入的文本推理，不等于已经使用工具。

SLAKE 英文数据实际规模是 **train 4,919、validation 1,053、test 1,061**；对应图像路径数为 450、96、96。按题目 ID、图像路径、图像与问题组合检查，三个原始划分的两两交集均为零。该检查不等于完成像素近重复或患者级排重。另外，已有 test 多次 rollout 的难度分析文件，不能宣称 test 从未被分析；本次未发现其题目进入上述训练 parquet，但仍需控制反复看 test 调参的选择偏差。

正式结果中，R1 的 MedEvalKit 非 judge 总正确率为 **67.30%**（OPEN 采用 EM，CLOSE 采用原规则）；R2.1 和 R3 的开放题 judge 加闭合题原评分的总体分数为 **76.44%**。这两个最优值来自不同实验、不同评分方式，不能写成同一个 checkpoint 同时取得两项最优成绩。

### 6 多模态训练基础设施排障

已保留两项 SGLang 补丁：一项根据上游修复对齐 Qwen3-VL 的视觉权重前缀 `model.visual.* → visual.*`；另一项为每次 pickle 分配独立 shared-memory segment，处理多候选图像 rollout 中共享内存被提前释放的问题。

此外，建立合成红框和医学 detection 的后端对照。对 **580 条 SLAKE detection** 的原始 JSONL 重新汇总，SGLang 与 vLLM 的平均 bbox IoU 分别为 **0.2523、0.2882**，两边均成功解析 580 个框。结果说明“输出合法坐标”与“视觉 grounding 一致”是两件事；不能仅凭模型服务成功启动就相信训练环境正确。


### 7 早期实验与相关前置工作

`Med_Vision/verl` 保留了 Qwen2.5-VL／Qwen3-VL 的医学 GRPO、DeepEyes 适配、ZoomIn 与检索、多轮工具和 KL 对照。部分运行达到 78、25 或 240 等训练步骤，能够证明开展过实际训练；这些运行的数据、预算和 reward 不同，不能拼成同一条性能增长曲线。部分早期目录目前仅剩 checkpoint 指针，不代表仍持有完整可复现权重。

多模态 Jupyter sandbox 的本地改动包括关闭 IPython history、限制持久化状态、TTL、幂等关闭和 kernel 清理。已有两组压测：48 会话配置下请求成功 2,448/2,496（98.077%），96 会话配置下为 2,347/2,496（94.030%）。分母是 init 与 follow 请求，不是会话；负载不同，也不能说成功率从 94%“优化到”98%。这些记录适合展示对工具环境稳定性和资源生命周期的理解。

另找到 Qwen2.5-VL 医学混合 LoRA SFT（本地历史记录，未分发）：rank 8，医学对话、分割及 PubMedVision 等混合任务，有 adapter 和完成记录。它可作为相关前置经历，尚不能把该 adapter 与后续 TWI GRPO 画成已证实的权重继承链。

最后两条分支应标为“已有部分资产”：原生 Thinking 模型当前仅确认基线与数据，相关 recipe 缺失；新 `zoom_in+retrieve` 分支确认实现、数据和 smoke，尚未找到训练完成记录。不要将所有目录都写成已完成的 RL 方法。

### 2 工具收益四类分析

该次 Qwen3.5-9B Agent 设置了 `require_server_tool_before_answer=true`，要求先调用外部工具，不能解释为已经学会自由选择是否调用。对 9,997 条 direct 与 agentic 结果逐条配对后得到：

| direct | agentic | 数量 | 占比 | 实际解释 |
|---|---|---:|---:|---|
| 对 | 对 | 8,944 | 89.47% | 这次 direct 已可答对；无法据此证明工具绝对无用 |
| 错 | 对 | 199 | 1.99% | 工具流程相对 direct 出现改善，值得检查是哪一步提供帮助 |
| 对 | 错 | 450 | 4.50% | 工具流程相对 direct 出现退化，值得检查误调用、误读和答案丢失 |
| 错 | 错 | 404 | 4.04% | 当前两条流程均未解决 |

净变化为 `199 − 450 = −251` 题，与两条流程正确数之差吻合。Agentic 有 215 条 `no_answer`，其中 196 条位于“direct 对、agentic 错”组；summary 的 `failed=0` 并不表示每题都产生了有效答案。这是比笼统归因于视觉工具错误更具体的排障入口。原分析中的旧目录名不能作为模型归属依据；本次逐条比对确认这些结果对应当前标注为 Qwen3.5-9B 的两份预测。部分无答案字段仅有 `null` 与空字符串的规范化差异。

这些是**配对流程比较**，还不是严格的工具因果效应：prompt、生成长度、采样和中间步骤也可能影响答案。后续应固定模型和预算，加入无效观察、打乱观察等对照，才能更有把握地把改善归因于工具提供的信息。

### 3 不适合直接作为简历成绩的数字

| 数字或现象 | 限制 | 合适用法 |
|---|---|---|
| 100 题正确 39→46、格式错误事件 15→1 | 100/100 与 SFT 输入池重合 | 解释协议学习与回归检查，不能称独立测试提升 |
| 3,000 题 direct 与 SFT agent 对比 | 与 SFT 输入池存在题目及图像重合 | 历史行为诊断；重建干净测试后再给泛化结论 |
| 教师 `with_answer` 的 49/50 或 canvas 10/10 | 生成过程可用参考答案或参考框 | 数据生成与接口 smoke，不是模型测试准确率 |
| Med_Vision 早期部分日志名含 `acc/mean@1` | 对应 med-reason／deepeyes_retrieve 评分返回复合 reward | 先追评分代码，必要时改称 validation reward |
| 训练日志中的 validation 上升 | 不同子集、judge、工具组合可能不同 | 监控优化行为，不替代统一 final test |
| 20 条裁剪实验从 30% 到 45% | 定向小样本；完整 1,053 题结果不支持普遍提升 | 说明为何需要扩样验证，不能只挑小样本正结果 |
| 上游仓库存在许多 git modified | 部分只是文件权限变化 | 只统计确实修改的代码和产生的实验 |

## 四 需要正视的实验问题

**早期 SFT 的数据隔离不足。** 1,791 条 SFT 输入池含 SLAKE test 64 条、validation 55 条及 VQA-RAD test 38 条。与 3,000 条评测集按 ID 重合 102 条；按图像路径与问题联合匹配重合 127 条，说明仅查 ID 会遗漏不同前缀指向的同一题。按图像路径，582 条评测记录涉及 112 张与 SFT 输入池相同的图像。重新评测旧模型时简单删除重复题仍不足以消除图像熟悉性，最好按图像划分重建数据并重训。

**早期 PMC-VQA 工具分支也有图像交叉。** `Med_Vision/verl` 的 `pmc-vqa-tool` train/test 为 1,600/400 条，唯一图像为 1,225/379，交集 164 张，占测试唯一图像约 43.27%。另一个 `reason` 分支按图像路径检查没有交集；不能把一个分支的问题扩大到全部实验。后续 SLAKE CoT 的独立划分应单独评价。

**指标字段需追溯到具体代码。** Med_Vision 的部分旧 recipe 直接返回复合 reward，却出现在日志的 acc 字段；较后的 agentic_rl recipe 已分别返回 `score` 与二值 `acc`，不能把所有训练准确率都说成复合奖励。

**reward 可能鼓励没有价值的工具调用。** 一版工具奖励近似为 `0.5×答案正确 + 0.3×格式正确 + 0.2×答对且用过工具`，较多调用之后才有额外惩罚。只要直接就能答对，补一次无关调用仍可能得到额外分数。需要把“调用发生”与“提供帮助”分开。

**裁剪实验含标注辅助。** 1,053 条实验中，194 条 crop 根据问题或参考答案匹配 detection label，776 条使用图像所有检测框的 union，83 条回退为原图。它适合分析上下文丢失及工具潜力，不能视为线上 Agent 自动定位的结果；标注框条件也不保证一定是最优裁剪，所以不应把它当成严格性能上界。

**后端和评测器属于实验条件。** 不同后端的视觉处理可能带来差异；EM 对简短标准答案敏感，judge 则可能接受同义表达，也可能误接受不完整的病名列表。应保留两种评分、真实请求参数及逐题错误分析，避免仅优化单一数字。

## 七 项目改进路线

### 优先级一 修复评测与证据链

| 工作 | 具体操作 | 验收标准 |
|---|---|---|
| 统一数据身份 | 保存 source、split、question ID、image hash、可得的 patient/study ID；检查跨源重复 | train/dev/test 的题目与图像交集为零；可疑近重复有处理记录 |
| 重建早期 SFT | 从划分后的 train 生成教师轨迹与筛选；留出完全独立 dev | 清除旧官方 test/validation 混入；学生输入无答案和 GT 区域 |
| 固定评测协议 | 用 manifest 绑定模型、prompt、backend、视觉预处理、真实请求参数、judge | 每个数字能追溯至逐题预测与实际运行日志 |
| 重新建立主表 | 先评测 base、CoT R1、语义 judge 方案和代表性 Agent checkpoint | 同一集合与评分方式；EM、judge、成本分别报告 |
| 保护 test | 用 dev 选 reward、seed、checkpoint 和 router 阈值；一次性报告 test | 不再根据反复查看 test 的结果选择“最好配置” |

先完成这些，才能把当前已有结果升级为更可信的研究结论。对已经训练过污染数据的模型，仅换一个评分脚本不能恢复独立测试条件。

### 优先级二 让工具调用产生净收益

先构建按图像划分的 direct／tool 配对池，并将错误分成：定位错误、工具执行错误、工具结果不可靠、观察误读、答案被覆盖、无答案与截断。人工抽查各类代表样本，尤其是 450 条流程退化与 199 条改善；不要直接把自动标签当成因果事实。

建立以下最小对照：

| 策略 | 目的 |
|---|---|
| Direct | 不调用工具的质量和成本基线 |
| CoT without tools | 分离额外文本推理收益 |
| Fixed one-tool | 测量某种工具的平均效果 |
| Confidence threshold router | 简单、可解释的选择性调用基线 |
| Learned router | 学习不同问题与工具的条件收益 |
| Real versus shuffled observation | 检验收益是否依赖真实工具信息 |
| Failure injection | 检验超时、空 mask、错误 crop、低置信结果后的恢复 |

router 的候选目标可以写为 `预期答题质量 − λ×调用成本 − μ×错误风险`。λ 和 μ 在 dev 上选择。记录准确率与延迟／调用数的 Pareto 曲线；不预设“降低 30% 调用”等尚未验证的项目成绩。

### 优先级三 重做更有针对性的后训练

**SFT 数据配比。** 同时保留直接作答、真正需要局部观察、需要知识检索、工具失败后修正或停止等轨迹。答案正确与过程可执行分别过滤；不再把“工具越多”当作更优示范。

**从简单 reward 开始。** 第一版只使用答案质量、必要的格式约束与温和调用／token 成本。先确认不导致永远不调工具，再尝试过程奖励。工具观察支持性由独立且经过校验的规则或评估器判断；不要奖励模型自述的帮助程度。

**控制变量。** 保持底座、数据、训练预算与评测协议固定，分别消融 reward、KL、组大小和中等难度筛选。监控组内 reward 方差、全对／全错组比例、熵、长度、截断和调用分布；同时保留 direct 基础能力。

**规范多轮训练。** 对工具消息角色、assistant loss mask、图像索引、chat template、状态释放和终止条件做小规模可检查验收，再放大 rollout。异常处理不应悄悄把工具错误改写成成功观察。

### 优先级四 强化多模态解释力

把现有 crop 消融拆成预测框、标注辅助框、随机框和全图条件；原图与局部图同时保留，按定位、计数、存在性、模态、疾病、多区域问题分层。对 GT 框结果注明实验条件，不把其作为可部署成绩。

给每个工具定义失效状态：空 mask、异常面积、目标不匹配、跨轮冲突和超时。要求模型在证据不足时复查、改用工具或结束；如果增加拒答，使用覆盖率与风险共同评价。

对训练与推理后端建立固定小诊断集，覆盖纯文本、单图、多图、合成 grounding、真实医学 grounding 与工具回注。后端变更后重新验证，避免把推理兼容问题误认为训练算法问题。

## 十二 如何理解任务、场景与可选手段

### 12.1 任务的核心是“有成本的证据获取与使用”

把本项目理解成一个有限预算的视觉决策过程更有解释力：模型接收图像和问题，判断当前证据是否足够；不足时选择工具和参数，检查返回结果，更新判断，再决定回答、继续观察或停止。医学知识、视觉表征、工具质量与策略共同决定结果。工具调用次数只描述行为，不能直接衡量能力。

这里至少有三种不同的研究任务：**图像问答**追求答案正确；**grounding／交互分割**追求区域定位或 mask 质量；**证据驱动的 Agent**还需要证明动作选择、观察消费和停止时机合理。SLAKE 上答对，不自动等于分割准确；mask IoU 提升，也不自动等于问答增益。MedSAM-Agent、IBISAgent 等可贡献交互机制，但其分割成绩不能直接与本项目 VQA 分数比较。

场景也决定工具价值：

| 场景 | 真正缺少什么 | 优先动作 | 需要防范的误解 |
| --- | --- | --- | --- |
| 全局模态、切面、器官识别 | 全局视觉与基本知识 | 原图直接作答，必要时无工具 CoT | 全图任务强制 crop 可能损失上下文 |
| 小结构、局部边界、低分辨率细节 | 可辨认的局部视觉证据 | 定位后保留原图并加入高分辨率 crop | 框得准不代表特征读得对 |
| 解剖位置、大小或空间关系 | 定位与可核验的结构信息 | segment／标记／测量，并保持原坐标关系 | overlay 可能遮挡病灶；分割模型也会失败 |
| 图像可见但医学含义不明确 | 概念与知识支持 | 来源可追溯的检索，再回到图像核对 | 检索不能证明某征象确实存在于这张图 |
| 工具与原图结论冲突 | 可靠性判断和恢复策略 | 验证、回退、更换观察方式或输出不确定性 | “工具更专业”不等于每个样本更可靠 |
| 多视图、3D 或病例级证据 | 当前输入之外的观测 | 单独设计新的任务和数据协议 | 现有 2D VQA 实验没有证明这些场景的能力 |

建议把当前研究边界固定为**离线、2D 医学图像问答中的选择性工具使用**，以局部细节和空间关系题作为重点分层；先证明这类任务的增益，再扩展到报告生成或 3D。上表是任务设计建议，不代表当前系统已经支持所有场景。

### 12.2 “再看一眼”为什么可能有用，为什么也可能无效

确定性的 crop 并没有给原始图像增加新的物理事实，但模型处理的是经过缩放、编码和 token 压缩后的表示。重新编码局部区域，可能让原先被压缩掉的细节进入模型可用的表示；这是表征层面的证据恢复。若错误来自医学知识或推理规则，单纯多裁几次图不一定有效。外部分割器还引入了另一个模型的计算与先验，同样需要质量检查。

本项目在 1,053 条 SLAKE English validation 上的全量验证实验中，judge 正确率分别为：原图 68.76%、原图加 crop 68.00%、仅 crop 62.11%。它提示“局部信息与全局语境如何结合”值得研究，但由于框包含问题／答案关联标注、union 和回退策略，不能据此宣布模型不需要局部视觉证据，也不能把这个实验称作理想 ROI 上界。

一个有价值的对照是：在相同总视觉 token 预算下比较原图高分辨率、原图加局部图、均匀多块切图和学习定位；再另做相同延迟或相同总推理成本的比较。这样可以分清收益来自“增加了算力”还是“把算力用到了更相关的位置”。

### 12.3 先诊断失败环节，再选优化方法

| 失败环节 | 可观察现象 | 最小诊断实验 | 对应手段 |
| --- | --- | --- | --- |
| 证据获取 | 漏调用、框偏移、目标未进入 crop | 比较预测区域与独立人工区域；保留整图对照 | 坐标与分辨率修复、定位监督、多尺度搜索 |
| 证据读取 | 区域正确，但小结构或属性读错 | 固定正确区域，测局部属性问答 | 领域视觉数据、分辨率预算、视觉编码器适配 |
| 证据整合 | 工具返回有用信息，答案忽略或误解它 | 固定动作前缀，替换／移除 observation 后续采样 | 观察消费训练、局部与全局融合、证据对齐蒸馏 |
| 行动选择 | 简单题也调用，难题却跳过 | 干净开发集做 direct／固定工具／可选工具配对 | 成本敏感 router、上下文 bandit，再考虑多轮 RL |
| 运行与停止 | 空输出、超时、截断、循环调用 | 对照执行日志、终止原因和剩余预算 | 明确错误协议、有限重试、缓存、回退与停止奖励 |

这套分类是本次为项目设计的诊断框架。与 MED 对工具增益、伤害和定位／使用错误的分析相呼应，但需要在本项目重新标注验证。[MED，第 3–4 节](https://arxiv.org/html/2602.01334v2)

**不要把所有错误压成“模型不够聪明”。** 如果主要是无答案和坐标转换问题，先做工程修复；如果框正确但读错，再投入视觉适配；如果能够读取却不使用，才重点研究 observation 的信用分配和蒸馏。

### 12.4 将“选择性调用”写成可学习的问题

部署时，策略只能看问题、原图、已有历史、可获得的置信特征和剩余预算，不能看正确答案、测试标注框或事后 judge。完整问题可以描述为部分可观测的序列决策：真实的工具可靠性与证据充分性不可直接观测，策略根据历史形成判断。但第一版不必做复杂多轮 RL，可以先学习一次性选择 direct、zoom 或 segment 的上下文 bandit／监督 router。

一个直观的工具价值分解是：

```text
预期净价值(a | 当前信息)
  = P(直接回答会错) × P(动作 a 能修复 | 直接会错)
  − P(直接回答会对) × P(动作 a 会破坏 | 直接会对)
  − λ × 动作成本
```

这些是需要用开发集估计的概率，不是推理时已知标签。对更强基座而言，可修复的错误可能更少，破坏既有正确答案的代价可能更大；这提供了三模型工具收益符号不同的一种解释假设，仍须排除 prompt、预算和工具执行差异。

训练可先采用 `答案得分 − 调用成本 − token／延迟成本 − 无效动作惩罚`，不同量纲需要归一化并在开发集选择权重。更清楚的报告方式是在若干固定预算下画准确率—成本 Pareto 曲线。不能只奖励“少调用”，否则模型可能全跳过；也不能奖励“答对且必须调用”，否则容易学到无意义调用。

首次调用前的 router 只能用当时可见的特征，如问题类型、图像尺寸，以及已经运行过的原图回答的校准置信度；若额外计算定位稳定性或先生成 Direct 答案，必须计入总成本。工具输出是否为空、mask 是否异常等信息，只能用于调用后的恢复、下一步选择或停止，不能提前作为首次调用特征。文字自报“我很有信心”不应直接当作可靠概率。需要报告校准、覆盖率与选择性错误率；加入拒答时同时报告覆盖率，避免通过大量不回答制造表面高准确率。

### 12.5 SFT、RL、OPD 各解决哪一层

| 手段 | 更适合解决的部分 | 当前资产如何复用 | 应先验证的条件 |
| --- | --- | --- | --- |
| SFT／纠错示范 | 工具格式、合法参数、观察消费、适时停止 | 使用已清理轨迹，同时保留直接回答与失败恢复样本 | 教师轨迹确实包含有用证据；训练测试隔离 |
| 工具专项课程 | 坐标、定位、旋转等动作执行能力 | 用训练集区域标注监督动作，再切回答任务 | 标注用于训练；医学图像增强不破坏左右／方向语义 |
| GRPO／RLVR | 多条合法路径的结果与成本权衡 | 已有多轮环境、reward 与训练基础设施 | reward 能区分有效动作；组内有区分度，日志覆盖退化 |
| 偏好优化 | 同题好坏轨迹之间的偏好 | 构造正确且低成本 vs 错误／高成本的配对 | 长度、格式与教师文风不能成为唯一偏好捷径 |
| On-policy distillation | 学生实际访问状态上的决策／证据使用 | 从学生 rollout 的前缀请求教师打分或指导 | 学生可学性、视觉信息对齐、教师信号质量 |
| 视觉表征或 token 适配 | 全局压缩导致的细节丢失、领域视觉差距 | crop／grounding 诊断结果可确定训练目标 | 先证实是读取瓶颈；改模型结构的成本高于修工具链 |

OPD 不是“教师生成答案，再做一次 SFT”的同义词。关键是监督发生在学生当前会访问的轨迹／前缀上，减少训练分布与推理分布错位。教师可以在训练时拥有标注 crop 或其他特权，但学生是否能从部署输入推断出同样证据，要独立验证；教师更强可能来自额外信息，不一定全是能内化的能力。这个担忧与你已有的 OPD 状态分布笔记（本地历史记录，未分发） 和 相关项目的 privilege illusion 讨论（本地历史记录，未分发） 相通，后者是另一个任务线的研究材料，不能合并成当前医学项目的实验结果。

### 12.6 三个值得保留的判断

1. **先问证据是否必要，再问模型是否用了证据。** 如果原图已经充分，删除 crop 后答案不变不等于模型不忠实；应在细节依赖题上做干预，并把充分性、正确性、使用情况分开标注。
2. **工具效用随模型和状态变化。** 固定全局工具排序难以覆盖样本差异。训练后 no-tool 能力增强，可能让原来的工具策略过度调用；应在多个 checkpoint 复评，而不是只看最终工具调用率。
3. **ROI 教师的价值与知识教师不同。** 前者可能提供学生部署时看不到的细节，后者提供可学习的推理或知识。将两者混在一个蒸馏奖励里，会使“内化了什么”难以解释。

这些是结合本地结果与相关研究提出的可检验推断，尚不是本项目已证明的结论。

## 十三 延伸研究假设与可执行实验

### 13.1 从现有四桶结果得到什么新的问题

Qwen3.5-9B 的历史内部池里，Direct 正确 9,394 题、错误 603 题；工具流程修复后者中的 199 题，同时使前者中的 450 题退化。由已有配对计数可以复算：原本错误的 603 题中修复率约 **33.00%**；原本正确的 9,394 题中退化率约 **4.79%**。看起来不大的破坏率，因为正确题基数更大，仍足以超过修复收益。这支持研究“避免伤害”的必要性，不能证明某一种 router 已有效。

如果事后知道每题哪个流程正确，两条固定历史结果的正确集合并集为 9,593／9,997，约 **95.96%**，比 Direct 高约 1.99 个百分点。这只是**事后集合并集参考**：使用了正确答案来挑选，未计双流程成本，也不是可部署成绩、泛化上界或新实验结果。它提示该池上存在互补性，同时提醒可挖掘的净空间可能有限。

215 条无答案已包含在四桶中，196 条落在退化组。优先区分超时、服务错误、解析失败、max tokens 和无终止动作，而不是直接把这些样本全部用于“复杂视觉推理”训练。修复运行错误与学会视觉推理，应分别报告。

### 13.2 假设 H1：选择性调用的主要收益可能先来自减少伤害

**假设。** 在强基座和简单题占比较高的医学 VQA 中，固定工具策略的破坏成本超过修复收益；允许跳过并识别失败，可在较低成本下保住 Direct 的正确题。

**最小实验。** 固定一个 checkpoint、解码和评测器，比较 Direct、固定单工具、允许零次调用、规则 router、学习 router；另外保留等预算无工具 CoT 对照。router 用干净训练／开发集学习；测试集只用一次定稿评估。以原始图像或病例分组，不把同一图的问答随机拆到两边。

**主指标。** 总正确率、配对 gain／harm、调用数、总视觉与文本 token、p50／p95 延迟、无答案率。按问题类型、目标区域尺度和基座分层，报告图像／病例聚类 bootstrap 区间，而不将同图多题视为独立样本。

**证伪条件。** 若减少调用同时大幅损失原有修复，或在相同预算下不优于 Direct／规则 router，就不能宣称学会了有效策略。原型成功可暂定为“准确率非劣且成本下降”，非劣阈值须事前确定并说明，而非看完 test 后挑阈值。

### 13.3 假设 H2：一部分失败来自“看到但不会用”，而非定位不准

**假设。** 部分题在正确局部证据已提供时仍失败，主要瓶颈是读取、全局融合或证据整合；更精细的 bbox reward 未必解决它。

**最小实验。** 在隔离的诊断集建立原图、人工有效 ROI 加原图、模型 ROI 加原图、错误 ROI 加原图四组；使用一致视觉 token 预算再做一个不等预算版本。人工 ROI 作为特权诊断条件单列，不能加入正式部署输入。对正确 ROI 仍失败的题，标注“细节仍不可辨”“属性读错”“属性读对但结论错”，最后一类再区分医学知识／规则不足和证据整合错误。

随后固定动作前缀，分别保留真实 observation、格式匹配的空 observation、同类错误 observation，重复生成后续答案。错误 observation 会引入分布变化，因此用多种控制并报告不自然输入比例；单个置空实验不能证明一般性的因果忠实。用同一 checkpoint、同一随机种子集合和相同后续预算减少无关差异。

**优化分支。** 读取瓶颈优先视觉训练或分辨率；整合瓶颈优先教师反馈、观察消费示范和 token 级蒸馏；工具本身错误则改质量检测与恢复。

**证伪条件。** 如果人工有效 ROI 已基本解决错误，主要应投入定位与证据获取；如果只有更多视觉 token 有效而 ROI 选择无额外收益，优先做预算和编码优化。

### 13.4 假设 H3：可部署证据的教师，比答案特权教师更适合训练可用策略

**假设。** 标注区域或答案提示带来的教师优势，可能部分来自不可迁移的信息；约束教师使用学生部署时可获得的图像和工具，有机会得到较小但更稳定的训练信号。

**最小实验。** 统一学生、训练样本和更新预算，采用同源教师并固定权重或 EMA 更新规则，在相同学生前缀上比较四组条件：原图；原图加预测 ROI；原图加标注 ROI；原图加同一标注 ROI 再加答案提示。各组保留原图，固定非实验 prompt 与视觉预算，另报告实际计算成本；后两类明确属于特权教师。先离线比较教师的准确率与学生可达性，再分别做小预算 SFT／OPD；教师优劣与学生最终增益分开统计。

**必要消融。** 学生 on-policy 前缀 vs 离线教师轨迹；均匀 token 权重 vs 故障环节权重；只对齐答案 vs 同时对齐工具决策；只做知识提示 vs 只做视觉特权。每次只改变一个核心因素，避免一次把所有方案都接入。

**证伪条件。** 如果特权 ROI 教师训练出的学生在干净外部测试上仍获得稳定收益，应承认特权监督有可迁移价值；是否内化了视觉证据获取或使用，仍需干预验证；如果可部署教师信号更弱且学生也更差，就不能仅凭“更真实”宣称更优。训练期标注的合法使用与测试泄漏是两回事。

### 13.5 假设 H4：带故障的工具环境，能检验策略是否学会恢复

**假设。** 训练中覆盖空 mask、偏移 crop、检索噪声、延迟和格式失败，可能帮助模型学到有限重试、换工具和回退；验证集故障只用于选择方案和测量已有能力，不能把验证过程本身解释为学习。

**最小实验。** 在可复现工具 wrapper 内预设故障类型、强度和随机种子，对同一批题逐级注入。比较无恢复、固定重试、规则回退、学习恢复。训练故障分布与测试故障类型留出一部分，避免只学会识别某个固定错误字符串。

**主指标。** 故障强度—任务性能曲线、恢复成功率、重复无效动作数、额外延迟和高置信错误率。使用专门的合法错误 observation，不能把服务异常静默伪装成“未发现病灶”。

**证伪条件。** 如果收益只在见过的错误模板上成立，或者通过大量拒答取得高准确率，就没有证明通用恢复能力。需配合覆盖率和成本报告。

### 13.6 推荐执行顺序与最小对照矩阵

先做 H1 和 H2 的轻量诊断，再决定是否投入 H3 的蒸馏与 H4 的多轮强化学习。以下是计划，不是已经完成的实验。

| 阶段 | 实验与对照 | 复用资产 | 进入下一步的判据 |
| --- | --- | --- | --- |
| P0：证据清理 | 重建干净 split、固定模型／后端／解码／judge；聚类去重 | 现有审核脚本、SLAKE 数据和测试结果 | 输入、样本、指标均可复算；旧受污染结果不作主结论 |
| P1：统一基线 | Direct、等预算 CoT、固定 crop、可选工具、规则 router | 工具服务器和配对评测脚本 | 确认 gain／harm 不是后端、prompt 或超时造成 |
| P2：瓶颈定位 | 训练／开发集上人工 ROI 诊断、观察替换、运行错误归因 | crop、mask、四桶轨迹 | 明确主要错误环节，决定训练目标 |
| P3：最小学习方案 | 同量干净 SFT；一次性学习 router；与规则 router 对照 | 教师轨迹和已有训练框架 | 同预算下收益或非劣成本优势，含置信区间 |
| P4：有选择地后训练 | outcome-only、成本项、工具课程／证据蒸馏逐项消融 | GRPO／OPD 相关工程与阅读积累 | 证明新增组件改善哪个环节，而非仅提升总体分数 |
| P5：外部验证 | 独立来源／模态留出、故障扰动、不同模型 | 现有医学基准接口 | 评估域外与故障稳健性，保留负结果 |

训练、开发和锁定测试承担不同角色。既有 test 已被多轮观察，后续阈值与模型选择只用开发集；重要最终结论最好增加新的外部留出集。重复使用 test 做研究诊断时，须披露其已被使用，不能再称完全未触碰。

### 13.7 有哪些可能的贡献，哪些还不能写成创新

最匹配现有资产的主线是：**医学视觉工具效用审计，加上由失败诊断驱动的选择性调用与证据学习**。交付可以是一个明确协议、可复算的 gain／harm 与故障分析、一个小而有效的 router，以及定位／读取／整合的消融。只有获得干净实验后，才能将“成本下降”“泛化提升”或“减少伤害”写成结果。

2026 年的 MED、With Tools or Because of Tools、视觉工具因果审计，以及视觉证据蒸馏工作已经覆盖了大量相近概念。因此不宜把“工具有时无效”“加一个 router”“使用 GRPO／OPD”单独宣称为首次创新。差异化需要落到医学任务的具体失效机制、可信的对照设计和有统计支持的改进。一个完整、诚实、能解释负结果的实习项目，已经比堆砌多个算法名称更有说服力。

面试中可以这样表达新增思考：

> 我后来把问题从“让模型学会调用工具”重新理解成“让模型在合适的时候获取并使用可靠视觉证据”。已有实验里，工具能修复一部分错误，也会破坏更多原本正确的回答，所以我会先拆分定位、读取、整合和运行失败，在统一预算下评估选择性调用，再决定是做视觉适配、工具课程还是 on-policy 蒸馏。这些是基于已有结果和文献提出的下一步计划，当前还没有把它们当作已完成成果。
